1. HTTP vs WebSocket

HTTP is half-duplex request/response: the client always initiates. WebSocket is full-duplex: either side can send at any time over a single TCP connection.

HTTP (polling): Client ──GET /messages──► Server ──200 OK──► Client (repeat every 2s) WebSocket (persistent): Client ──HTTP Upgrade──► Server (one-time handshake) Client ◄──────────────── Server (server pushes freely) Client ──────────────── ► Server (client sends freely)

2. WebSocket Handshake

The connection starts as HTTP and upgrades via the Upgrade: websocket header:

GET /stomp-ws HTTP/1.1
Host: localhost:8080
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZQ==
Sec-WebSocket-Version: 13

--- Server responds ---
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPL…

3. STOMP Protocol

STOMP is a text-based sub-protocol that runs inside the WebSocket connection. It adds destinations (named channels), commands (CONNECT, SEND, SUBSCRIBE, DISCONNECT), and headers.

STOMP Frame structure

COMMAND
header1:value1
header2:value2

Body (optional)^@

Key STOMP Commands

CONNECT              ← client opens a STOMP session
CONNECTED            ← server acks the CONNECT
SEND                 ← client publishes to a destination
SUBSCRIBE            ← client registers interest in a destination
MESSAGE              ← server delivers a message to a subscriber
UNSUBSCRIBE          ← client cancels a subscription
DISCONNECT           ← client closes the STOMP session
ERROR                ← server signals an error

Real STOMP SEND frame

SEND
destination:/app/chat.sendMessage
content-type:application/json
content-length:48

{"sender":"Alice","content":"Hello!","type":"CHAT"}
^@

4. Spring Destination Prefixes

Client SEND to /app/chat.sendMessage → Spring routes to @MessageMapping("/chat.sendMessage") → Controller logic runs → @SendTo("/topic/public") publishes result to broker Client SEND to /topic/public (bypasses controller, goes straight to broker) → Not recommended for untrusted input /user/{name}/queue/private ← server-to-user private messaging

5. In-Memory Broker vs External Broker

// In-memory (this demo):
registry.enableSimpleBroker("/topic", "/queue");

// Production — relay to RabbitMQ/ActiveMQ:
registry.enableStompBrokerRelay("/topic", "/queue")
        .setRelayHost("localhost")
        .setRelayPort(61613);   // STOMP port on RabbitMQ

6. SockJS Fallback

SockJS tries WebSocket first, then falls back to HTTP-based transports (xhr-streaming, xhr-polling, iframe) if WebSocket is blocked by a proxy. Spring Boot serves the SockJS endpoint automatically when you call .withSockJS() in the config.

7. Heartbeats

STOMP supports heartbeat negotiation. The server declares its send/receive intervals in the CONNECTED frame. Both sides then ping each other so dead connections are detected quickly.

CONNECTED
version:1.2
heart-beat:10000,10000   ← send every 10s, expect every 10s
